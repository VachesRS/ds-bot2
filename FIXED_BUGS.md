# 🛠️ Журнал исправленных багов и уязвимостей Kobi

В этом документе зафиксированы все баги и уязвимости, устранённые по результатам полного аудита проекта.

---

## 1. Веб-панель (Dashboard & Security)
- **[🔴 XSS Уязвимость] `web/templates/base.html`**:
  - `showToast` использовал `innerHTML` с неэкранированным текстом сообщения `${message}`.
  - **Исправление**: переход на безопасное создание DOM-узлов через `textContent`, исключающий выполнение произвольного JavaScript при отображении серверных ошибок.
- **[🔴 Подделка сессий] `web/server.py`**:
  - `COOKIE_SECRET` содержал статический fallback `"kobi-secure-secret-key-2026"`, что позволяло злоумышленнику выпустить подписанную cookie администратора для любого сервера.
  - **Исправление**: обязательная динамическая криптографическая генерация `secrets.token_hex(32)` при отсутствии переменной окружения.
- **[🟠 CSRF в OAuth2] `web/server.py`**:
  - В авторизации через Discord отсутствовал параметр `state`.
  - **Исправление**: генерация одноразового криптостойкого токена `state`, передача в Discord и сверка через защищённую cookie `kobi_oauth_state`.
- **[🟠 Защита прав доступа в реальном времени] `web/server.py`**:
  - `_check_guild_access` доверял кэшированному списку гильдий из OAuth сессии сроком до 7 дней даже после снятия прав администратора.
  - **Исправление**: проверка прав в реальном времени через прямое обращение к объекту участника `bot_guild.get_member(user_id)` / `fetch_member(user_id)`.
- **[🟠 Отключение Voice XP в панели] `web/templates/guild.html`**:
  - Чекбокс `levels_voice_xp_enabled` и `welcome_send_card` отсутствовали в списке `toggles` JS, из-за чего при снятии галочки параметр не передавался на сервер и всегда оставался включенным (`1`).
  - **Исправление**: добавлены в массив `toggles`.
- **[🟡 Безопасность Cookie] `web/server.py`**:
  - Добавлен флаг `secure=True` при работе через HTTPS / Cloudflare Tunnel / Reverse Proxy.

## 2. Автомодерация (`cogs/automod.py`)
- **[🔴 Обход автомодерации через редактирование сообщений]**:
  - Был зарегистрирован только `on_message`. Нарушители могли отправить безобидное сообщение («привет») и отредактировать его на спам/NSFW/инвайт.
  - **Исправление**: добавлен слушатель `on_message_edit` с проверкой изменённого контента и вложений.
- **[🔴 Защита от OOM / DoS через тяжелые файлы]**:
  - Вложения картинок скачивались целиком через `att.read()` без проверки размера.
  - **Исправление**: установлен жёсткий лимит 15 МБ на изображения перед вызовом `read()`, а при потоковой загрузке внешних URL установлен лимит чанков до 20 МБ даже при отсутствии заголовка `Content-Length`.
- **[🟡 Утечка ресурсов aiohttp]**:
  - Добавлен метод `cog_unload` с корректным закрытием сессии `self.session.close()`.

## 3. База данных (`database.py`)
- **[🔴 SQLite WAL Mode]**:
  - При высокой конкурентной нагрузке возникали блокировки `database is locked`.
  - **Исправление**: включен режим `PRAGMA journal_mode=WAL;` и `PRAGMA busy_timeout=5000;`.
- **[🟠 Вложенные соединения и дедлоки]**:
  - В функциях `set_feature_toggle` и `set_autorole` вызывался `get_guild_settings` внутри незакрытого блока `async with aiosqlite.connect()`.
  - **Исправление**: вызов вынесен за пределы активного соединения.
- **[🟠 Ошибка ранга #1 для новых пользователей]**:
  - В `get_user_rank` условие `COALESCE` было внутри подзапроса, из-за чего для нового пользователя возвращался `NULL` и ранг рассчитывался как 1.
  - **Исправление**: `COALESCE` вынесен наружу подзапроса.
- **[🟡 Защита от дублей в `add_temp_channel`]**:
  - Замена на `INSERT OR REPLACE INTO active_temp_channels`, предотвращающая падение бота с `sqlite3.IntegrityError: UNIQUE constraint failed`.

## 4. Команды модерации (`cogs/moderation.py`)
- **[🔴 Реализация системы варнов]**:
  - В коде полностью отсутствовали slash-команды для системы предупреждений, хотя функции БД были готовы.
  - **Исправление**: реализованы команды `/warn`, `/warnings`, `/unwarn`, `/clearwarns` с эмбедами и постраничным выводом.
- **[🔴 Алиас команды `/mute`]**:
  - Добавлена слэш-команда `/mute` как удобный алиас для `/timeout`.
- **[🔴 Уязвимость обхода иерархии в `/untimeout`]**:
  - Модераторы могли снимать тайм-аут с участников с ролью выше их собственной.
  - **Исправление**: добавлена строгая проверка `member.top_role >= interaction.user.top_role`.
- **[🟠 Защита от действий над ботом и самим собой]**:
  - В командах `/timeout`, `/mute`, `/kick`, `/ban`, `/warn` добавлены проверки `member.id == interaction.user.id`, `member.id == self.bot.user.id` и `member.bot`.
- **[🟡 Зависание интеракции кнопки закрытия в `/help`]**:
  - Добавлен `await interaction.response.defer()` перед удалением сообщения, устранивший ошибку "Взаимодействие не удалось".
- **[🟡 Deprecated параметр в `/ban`]**:
  - `delete_message_days` переведён на актуальный `delete_message_seconds`.

## 5. Облачная синхронизация (`cloud_sync.py`)
- **[🔴 Превышение лимита сообщений Discord (2000 символов)]**:
  - При большом количестве настроек/наград JSON превышал 2000 символов и вызов Discord API завершался ошибкой `400 Bad Request`, приводя к потере бэкапа.
  - **Исправление**: при размере конфигурации > 1700 символов файл автоматически сохраняется как вложение `kobi_settings.json` к сообщению.
- **[🔴 Ошибки парсинга при наличии бэктиков в сообщениях]**:
  - Использование `.rsplit("```", 1)` и поддержка чтения из закреплённых сообщений и вложений предотвращают поломку `JSONDecodeError`.
- **[🟠 Защита от затирания облачного бэкапа]**:
  - Если конфигурация не найдена, бэкап перезаписывается локальными данными только если в локальной БД действительно настроены параметры.
- **[🟡 Восстановление Voice XP]**:
  - В восстановление настроек уровней добавлен параметр `voice_xp_enabled`.

## 6. Ядро бота (`main.py`)
- **[🔴 Дублирование слэш-команд и Rate Limit]**:
  - Удалён избыточный цикл `copy_global_to + tree.sync(guild=guild)` в `on_ready`, вызывавший двойные команды в интерфейсе и HTTP 429.
- **[🟠 Гонка при восстановлении настроек]**:
  - Восстановление настроек из облака вызывается строго один раз при первом старте бота (`_settings_restored`), не перезатирая свежие данные при реконнектах Discord.
- **[🟠 Защита от перезаписи настроек при входе на сервер]**:
  - В `on_guild_join` вызывается `restore_guild_settings_from_discord` вместо перезаписи дефолтными настройками.
- **[🟠 Бесконечный цикл перезапуска при отсутствии интентов]**:
  - Перехват `discord.errors.PrivilegedIntentsRequired` с понятным сообщением об ошибке и остановкой процесса.

## 8. Целостность данных, Event Loop и очистка памяти (Последние фиксы)
- **[🔴 Устранение дубликата декоратора `/timeout` (`cogs/moderation.py`)]**:
  - Был задвоен декоратор `@app_commands.command(name="timeout")` и заголовок секции, из-за чего падала синхронизация slash-команд.
  - **Исправление**: удалена лишняя копия декоратора.
- **[🔴 Атомарное начисление XP без race condition (`database.py`)]**:
  - Ранее начисление опыта выполнялось по схеме read-modify-write (`SELECT` -> расчёт нового опыта в Python -> `INSERT/UPDATE`), из-за чего одновременные сообщения от одного пользователя перезатирали опыт друг друга.
  - **Исправление**: переход на атомарный SQL UPSERT `INSERT ... ON CONFLICT DO UPDATE SET xp = user_levels.xp + excluded.xp RETURNING xp, level`. Приращение опыта происходит строго на уровне движка SQLite.
- **[🟠 Неблокирующая генерация карточек Pillow (`cogs/levels.py` и `cogs/welcome.py`)]**:
  - Отрисовка графических карточек ранга и открыток новичков (LANCZOS-сэмплинг, эффекты, сжатие PNG) выполнялась прямо в основном потоке asyncio event loop, блокируя обработку событий Discord на 100-300 мс.
  - **Исправление**: тяжёлая отрисовка и сохранение в PNG вынесены в синхронные функции `_draw_rank_card_sync` и `_draw_welcome_card_sync` с запуском через `asyncio.to_thread`.
- **[🟠 Устранение утечки памяти в `message_timestamps` (`cogs/automod.py`)]**:
  - Словарь `self.message_timestamps` бесконечно копил ключи пользователей, которые когда-либо отправляли сообщения, а при очистке после спама сохранялся пустой список `[]`.
  - **Исправление**: добавлен фоновый планировщик `@tasks.loop(minutes=5)` для автоматического удаления устаревших ключей (старше 60 секунд), замена очистки на `self.message_timestamps.pop(user_key, None)` и инлайн-очистка при превышении лимита словаря.
